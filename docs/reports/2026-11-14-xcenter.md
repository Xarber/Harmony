# X-Center production verification

Production serves Harmony Web 0.1.0 from commit `588e8ec036aebe03aef6cb0b58a892fd63b1a9b8`. The first activation returned HTTP 404 and rolled back. The second activation succeeded with a retry window after the Nginx reload. HTTPS health, exact build metadata, manifest MIME type and service-worker script returned successfully. The browser QA route returned 404 as expected.

The live browser showed the first-visit landing page, opened the library from its call to action, displayed production Settings without developer options, and reopened directly in the library on return to the root URL. The earlier loopback browser run covered playback with generated audio, seeking, draft handling, offline reopening and update behavior. Local checks passed 7 Node tests and 21 Swift tests after replacing a fixed playback delay with a bounded progress check.

[GitHub Actions build 43592619392](https://github.com/Xarber/Harmony/actions/runs/43592619392) was dispatched on `testing` for production web export, Swift tests, macOS, iOS device IPA and iOS Simulator packaging. Full Xcode was unavailable locally. Physical Apple devices, signing, native installation and browser home-screen installation are outside the evidence collected here.
